# 代理需求整理

> 优化第 2 步：先把需求说清楚，再动配置。本文只记录需求和思路，不含节点地址、端口、密码等配置细节。
> 配置里具体的规则和策略组以 Surge 线上 profile 为准；本仓库的 `List/` 是从 SukkaW/Surge 自动生成的规则集。

## 评价代理 IP 的三个维度

| 维度 | 含义 | 影响 |
|---|---|---|
| **速度** | 延迟、带宽 | 日常浏览、视频、下载的体验 |
| **IP 纯净度** | IP 是否被网站标记为机房 IP 或被滥用过 | 是否频繁弹验证码，登录、支付是否触发风控 |
| **国家** | IP 所在地 | 地区限定内容、服务可用性 |

这三个维度经常互相冲突：快的节点往往不干净，干净的节点（例如家宽）往往慢，而且贵。

## 现状与问题

- po0 的香港节点**速度快，但 IP 很黑**，经常被要求做人机验证。
- 不用它又会变慢。所以不追求"全局都用干净 IP"，而是**默认走快节点，只把会弹验证的网站挑出来，交给纯净 IP**。

## 目标

1. **快**：默认流量走速度优先的节点。
2. **不自动弹验证**（IP 纯净度）：会弹验证码或触发风控的网站，固定走纯净 IP 的代理。
   - 做法：**手动维护规则**，遇到哪个网页要验证，就把它的域名加进"纯净 IP"规则。
   - 需要登录、验证码、支付的会话要**固定出口**，不能挂在会自动切换的组下，否则中途换 IP 反而更容易触发风控。
3. **自动 fallback 到 AUTO**：手动选的节点不可用时，自动回退到 AUTO（自动测速选择）。
4. **中转分组用 fallback**：中转节点按优先级排列，前一个不可用就用下一个。

### 目标与当前配置的对照（2026-09-26）

| 目标 | 当前状态 |
|---|---|
| 默认走快节点 | 已有：`PROXY` → 手动选择的 `SELECT` |
| 失败回退 AUTO | 已有：`PROXY` 下面挂了 `SELECT失败自动回退AUTO = fallback, SELECT, AUTO` |

| 按需把验证网站加进纯净 IP 规则 | **待建**：还没有一个专门的"遇到验证就往里加"的规则清单和加规则的流程 |

## 脚本需求：网络切换时防止银行 App 走错网络

**问题**：切换网络（例如 Wi-Fi 与蜂窝之间切换）时，VPN 可能会重启。重启的几秒里没有代理，本不该连接国内网络的银行 App 会直接连出去。

**思路 A：切换后短暂断网**

网络切换后的 3–5 秒内禁止连接，等代理恢复后再放行。

- 可行性：nobyda 的文章给出了现成做法。用 Surge 的**事件脚本**监听网络变化，记下切换时间；再用**规则脚本**判断当前是否还在时间窗口内；最后用**逻辑规则**（AND / OR / NOT）组合，在窗口内拦截请求。文章给的窗口是 15 秒，可以按需调短。
- 限制（文章所述）：信号不稳定时会被误触发；有些请求不是由网络切换引起的，拦不住。
- **待确认**：VPN 重启期间 Surge 自己也可能不在，这时规则根本不生效。要先确认 "VPN 重启" 指的是哪一层（Surge 的虚拟网卡重建，还是 Surge 进程本身重启），拦截方案才有意义。

**思路 B：只允许从指定 IP 登录**

让银行账号只允许从某些 IP 登录。原理上似乎可行，但还需要分析：

- 这通常是银行或服务方提供的功能，不在 Surge 里配置。要先确认目标银行是否支持。
- 如果指的是在 Surge 里限制 App 只能经由指定出口连接，那就相当于"按进程固定策略 + 失败时拒绝，而不是回退到直连"。它能不能在 VPN 重启的空档生效，和思路 A 是同一个问题。

## 参考

- [Accademia/Clash_Configuration_Template](https://github.com/Accademia/Clash_Configuration_Template)：Clash 配置模板。节点按属性分组（住宅 IP、中转、显示归属地），用代理链让落地 IP 所在国保持稳定、不频繁跳动；另外讲了分流规则前置的顺序和防 DNS 泄漏。可借鉴它"按 IP 属性分组"的思路。
- [nobyda：Surge 网络防火墙](https://nobyda.github.io/2021/06/08/Surge_network_firewall/)：用事件脚本、规则脚本、逻辑规则实现"网络切换后一段时间内拦截请求"，对应上面的思路 A。
